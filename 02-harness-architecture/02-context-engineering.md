# 02. 컨텍스트 엔지니어링 및 토큰 예산 관리 (Context Engineering)

LLM의 컨텍스트 윈도우가 100만~200만 토큰으로 확장되었음에도 불구하고, **단일 프롬프트에 불필요하게 많은 지식을 주입하면 모델의 주의력 집중(Attention Recall)과 추론 품질이 급격히 저하**됩니다. 이를 효율적으로 관리하기 위한 엔지니어링 원칙을 다룹니다.

---

## 1. 컨텍스트 예산 배분 원칙 (Context Budgeting)

일반적인 코딩 에이전트 세션의 컨텍스트 윈도우를 100%로 보았을 때의 이상적인 예산 배분:

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 시스템 프롬프트 및 코어 하네스 (AGENTS.md): 5% ~ 10%    │
├─────────────────────────────────────────────────────────────┤
│ 2. 온디맨드 로드된 지식 (docs/ai/*, SKILL.md): 15% ~ 25%   │
├─────────────────────────────────────────────────────────────┤
│ 3. 작업 대상 코드 및 직접 참조 파일: 30% ~ 40%              │
├─────────────────────────────────────────────────────────────┤
│ 4. 대화 히스토리 및 터미널 출력(린트/테스트): 20% ~ 30%     │
├─────────────────────────────────────────────────────────────┤
│ 5. 모델 추론 및 계획 공간 (Free Buffer): 10% ~ 20%          │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 파일 크기 및 길이 관리 기준 (Length Guardrails)

프로젝트 내 코드 파일과 가이드 문서 파일이 과도하게 길어지면 에이전트가 코드를 부분적으로 누락하거나 환각을 일으킬 확률이 급증합니다.

### 권장 파일 길이 기준표

| 대상 파일 유형 | 권장 길이 (Lines) | 경고 기준 (Lines) | 분할/조치 방안 |
|---|---|---|---|
| **Root `AGENTS.md`** | 80 ~ 120 | 200 초과 | 세부 내용을 `docs/ai/`로 분리하고 라우터만 유지 |
| **도메인 가이드 (`docs/ai/*.md`)** | 100 ~ 250 | 400 초과 | 하위 주제별 파일로 분할 |
| **React/Next.js Screen/Page** | 150 ~ 250 | 350 초과 | 하위 컴포넌트(`_components/`) 및 훅 분리 |
| **React Native Screen** | 200 ~ 300 | 400 초과 | 서브 뷰 또는 프레젠테이셔널 컴포넌트 추출 |
| **Custom Hook** | 80 ~ 150 | 250 초과 | 비즈니스 로직과 API 페칭 로직 분리 |
| **Backend Service / Controller** | 150 ~ 250 | 400 초과 | 도메인별 세부 서비스/핸들러 분리 |

## 3. 점진적 공개(Progressive Disclosure) 패턴

모든 규칙을 항상 주입하지 않고, **에이전트가 필요한 순간에 스스로 문서를 읽도록 강제**하는 구조입니다.

### 패턴 구현 방법

1. **상황별 트리거 키워드 지정**
   - API 작업 시: `docs/ai/API.md`
   - 스타일 수정 시: `docs/ai/TAILWIND_STYLING_GUIDE.md`
   - 빌드/배포 관련 시: `docs/ai/BRANCH_RELEASE_POLICY.md`
2. **에이전트에게 사전 로드 지시문 부여**
   ```markdown
   > 작업 전 해당 영역의 전용 가이드를 반드시 view_file로 읽고 시작하십시오.
   ```
3. **토큰 절약 효과**
   - 초기 진입 시 소모 토큰: ~1,000 토큰 (전체 주입 시: ~15,000 토큰 대비 90% 이상 절감)
   - 작업 대상 영역의 규칙에만 집중하므로 오답률 대폭 감소
