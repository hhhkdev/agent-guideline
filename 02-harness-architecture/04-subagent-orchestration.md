# 04. 서브에이전트 오케스트레이션 및 가상 회사 아키텍처 (Subagent Orchestration)

단일 에이전트가 모든 작업을 처리하려고 하면 컨텍스트 윈도우 한계, 역할 혼선, 주의력 분산으로 인해 실패 확률이 증가합니다. 본 가이드는 **서브에이전트를 가상 회사(Virtual Software Company)의 부서 및 팀원처럼 조직하고 오케스트레이션하는 방법**을 다룹니다.

---

## 1. 서브에이전트의 핵심 멘탈 모델: "자율 가상 회사"

서브에이전트 시스템은 마치 스타트업 한 곳을 차려놓고 각 포지션에 전문 인력을 배치한 것과 같습니다.

```
                  ┌──────────────────────┐
                  │    Parent Agent      │
                  │   (CEO / Dispatcher) │
                  └──────────┬───────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│ Product Manager │ │ Tech Architect  │ │ Growth Marketer │
│ (PRD / User Flow│ │ (System Design) │ │ (Funnel / GTM)  │
└────────┬────────┘ └────────┬────────┘ └────────┬────────┘
         │                   │                   │
         └─────────┬─────────┴─────────┬─────────┘
                   ▼                   ▼
          ┌─────────────────┐ ┌─────────────────┐
          │ Frontend Worker │ │ Backend Worker  │
          │ (React/Flutter) │ │ (Spring/Node)   │
          └────────┬────────┘ └────────┬────────┘
                   │                   │
                   └─────────┬─────────┘
                             ▼
                    ┌─────────────────┐
                    │   QA Guardian   │
                    │ (Linter/Analyze)│
                    └─────────────────┘
```

## 2. 언제 단일 에이전트 vs 언제 서브에이전트를 쓰는가?

| 상황 | 단일 에이전트 (Single Agent) | 서브에이전트 분할 (Subagents) |
|---|---|---|
| **작업 범위** | 단일 파일 수정, 버그 패치, 린트 오류 수정 | 다중 모듈 신규 기능 개발, 기획+개발+마케팅 동시 진행 |
| **컨텍스트 크기** | 참조 파일이 1~3개 내외 (< 5,000 토큰) | 거대 코드베이스 전수 분석, 수십 개 파일 리팩토링 |
| **작업 성격** | 결정론적이고 단순 반복적인 작업 | 관점 대립(기획자 vs 개발자 vs QA 검증관)이 필요한 작업 |
| **비용 효율** | 오버헤드 최소, 즉각 실행 | 서브에이전트 통신 비용 발생하나 작업 무결성 극대화 |

## 3. 서브에이전트 4대 토폴로지 (Organizational Patterns)

### ① 계층형 매니저-워커 (Hierarchical Manager-Worker)
- **구조**: 최상위 매니저(CEO)가 요구사항을 세부 태스크로 쪼개어 Specialist에게 할당하고 결과만 취합.
- **장점**: 매니저의 컨텍스트가 워커의 지저분한 로그나 중간 산출물로 오염되지 않음.
- **적용**: Antigravity의 `invoke_subagent`, MetaGPT, ChatDev 기본 구조.

### ② 순차 파이프라인 (Sequential Assembly Line)
- **구조**: `기획(PRD)` → `설계(Architecture)` → `구현(Coding)` → `검증(QA)` 순으로 산출물이 다음 단계로 전달됨.
- **장점**: 단계별 검증 게이트(Verification Gate)를 통과하지 못하면 다음 단계로 넘어가지 않음.

### ③ 전문가 합의/토론 (Specialist Debate / Multi-Persona)
- **구조**: 프론트엔드 개발자와 백엔드 개발자 에이전트가 API DTO 규격을 두고 토론하여 최적의 인터페이스 합의.
- **장점**: 단일 모델의 편향(Bias)이나 실수 방지.

### ④ 백그라운드 워커 (Background Daemon Task)
- **구조**: 빌드, 테스트, 배포, 모니터링 작업을 백그라운드에 띄워두고 이벤트 수신 대기.

## 4. 토큰 경제학 및 비용 통제 (Token Economics)

서브에이전트를 잘못 다루면 **루프에 빠져 수백만 토큰이 순식간에 소모**될 수 있습니다.

1. **상한 예산 (Token Cap) 설정**: 서브에이전트 호출 시 최대 실행 스텝(Max Steps) 또는 타임아웃을 강제.
2. **요약 전달 원칙 (Summary-Only Return)**: 서브에이전트가 수천 줄의 파일 내용을 부모에게 그대로 반환하지 않고, 핵심 결과(Diff, 결론, 파일 경로)만 간결히 보고하도록 지시.
3. **독립 워크스페이스 분리**: 서브에이전트가 서로의 임시 파일을 건드리지 않도록 `branch` 또는 격리된 디렉터리 지정.

## 5. 실무 서브에이전트 오케스트레이션 코드 예시

### Antigravity 서브에이전트 호출 규격
```python
invoke_subagent(
    Subagents=[
        {
            "TypeName": "research",
            "Role": "PRD & Product Planner",
            "Prompt": "teumteum-mobile의 홈 위젯 개선을 위한 PRD와 사용자 저니 맵을 작성하고 docs/ai/PRD.md에 저장하라."
        },
        {
            "TypeName": "self",
            "Role": "iOS Swift Engineer",
            "Prompt": "targets/home-widget/의 WidgetKit 뷰를 갱신하여 10pt 고정 줄간격과 다크모드 대비율을 맞추어라."
        }
    ]
)
```
