# 01. 메타 프롬프트 컬렉션 (Meta-Prompts)

메타 프롬프트는 에이전트가 새로운 하네스 문서, 스킬, 프롬프트, 테스트 슈트를 자체 생성하거나 프로젝트 분석을 수행할 때 사용하는 상위 수준의 프롬프트 템플릿입니다.

---

## 1. 신규 프로젝트 하네스 생성 메타 프롬프트

> **용도**: 신규 레포지토리를 만들었거나 기존 레포지토리에 처음 에이전트 환경을 구축할 때 사용.

```markdown
당신은 최고의 AI 하네스 설계자입니다.
대상 프로젝트의 파일 구조와 의존성 파일(package.json, build.gradle, pubspec.yaml 등)을 분석하여 다음 산출물을 작성해주세요.

1. 프로젝트 최상위 진입점인 `AGENTS.md`:
   - 100~150줄 이내로 압축
   - 프로젝트 스택 요약 표
   - 의도별 문서 라우터 표 (/feat, /api, /refactor, /review)
   - 프로젝트 고유의 3대 골든 룰
   - 세션 종료 전 반드시 0 에러로 통과해야 하는 단일 검증 명령어(Verification Gate)

2. `docs/ai/` 하위 모듈형 가이드 문서:
   - `ARCHITECTURE.md`: 계층 구조, 디렉터리 역할, 컴포넌트 분할 기준
   - `CONVENTIONS.md`: 네이밍, 모범 사례, 금지 패턴
   - `API.md` (필요 시): 통신 계층, 쿼리/캐시 관리 정책
   - `TECH_DEBT.md`: 발견된 기술 부채 및 체크리스트

모든 문서는 실무에서 즉시 활용할 수 있도록 모호한 설명을 배제하고 실제 코드 예시와 파일 경로를 포함하세요.
```

---

## 2. 도메인 특화 Skill 생성 메타 프롬프트

> **용도**: 반복되는 복잡한 작업(예: iOS 네이티브 빌드, 특정 라이브러리 연동)을 재사용 가능한 `SKILL.md`로 패키징할 때 사용.

```markdown
당신은 에이전트 스킬(Skill) 설계 전문가입니다.
다음 작업에 대해 Antigravity 및 Codex 표준 규격의 `SKILL.md`를 작성해주세요.

작업 설명: {TASK_DESCRIPTION}
참조 파일 및 도메인 규칙: {REFERENCE_RULES}

요구사항:
1. 상단 YAML Frontmatter에 `name`과 에이전트가 언제 이 스킬을 호출해야 하는지 명확히 규정하는 2-3문장의 `description`을 작성하세요.
2. 본문에는 런타임 환경 확립 단계, 핵심 설계 원칙, 피해야 할 안티패턴, 검증 체크리스트를 번호 매김 순서로 명확히 작성하세요.
3. 추상적인 지침 대신 프로젝트의 실제 CLI 명령어, 정규식, 코드 패턴을 구체적으로 포함하세요.
```

## 3. 에이전트 디버깅 및 자가 치유(Self-Healing) 유도 프롬프트

```markdown
현재 터미널 검증 결과 에러가 발생했습니다.
아래 에러 로그를 분석하여 즉시 수정하되, 다음 원칙을 지키세요:
1. 단순히 에러를 숨기기 위해 `any` 타입을 쓰거나 린트 주석(`eslint-disable`)을 추가하지 마십시오.
2. 근본적인 타입 정의 불일치 또는 런타임 불일치 원인을 찾아 수정하십시오.
3. 수정 후 반드시 `{VERIFICATION_COMMAND}`를 재실행하여 문제가 완전히 해결되었음을 입증하십시오.
```
